# Допущения ЛР3

- `ArchPlan3.md` и приложенное ТЗ отсутствуют в рабочем дереве; сопоставление с ними невозможно. Требования взяты из запроса, имена источников — из кода `main`.
- В отличие от локальных заметок об исходной ЛР1, на `main` отзывы и снимки онлайна используются из PostgreSQL ODS. DDS также использует PostgreSQL.
- Ветка `origin/lab3_feature_a` доступна как локальная ссылка и содержит реализацию нескольких тех же файлов и компонентов. Их автоматическое объединение не гарантировано; при слиянии потребуется согласовать реализацию витрин, DAG и инфраструктуры, не запускать оба варианта одновременно.
- Исторические отзывы группируются по дате создания UTC и текущей версии отзыва; изменения голоса пересчитывают историю. Пропущенные даты и неполный сбор Steam не означают нулевую активность.
- `dds_facts_dag` каждый раз выбирает первые по дате отзывы в пределах `reviews_limit`, без пагинации; текущие версии отзывов за пределами лимита могут не попасть в факт. Для сбора онлайна выбираются первые `batch_size` игр из запроса без `ORDER BY`. Данные не представляют равномерную выборку.
- При загрузке DDS отсутствующее `voted_up` приводится к `false`; доля положительных относится к этим нормализованным значениям, а не обязательно к полной оценке Steam.
- В `steam_player_stats_etl` файлы промежуточных результатов именуются только по `ds`. DAG ограничен `max_active_runs=1`, но повторные прогоны за ту же дату перезаписывают предыдущие файлы; при изменении ограничения параллельные интервалы смогут конфликтовать.
- Свежесть за сутки — операционное требование: при отсутствии данных за закрытый интервал проверка должна сигнализировать, а не создавать фиктивные записи.
- `dds_facts_dag` ожидает все восемь трёхчасовых запусков онлайна за интервал. При `catchup=False` после первого запуска стека часть интервалов может отсутствовать; задним числом Steam возвращает текущий онлайн, а не исторический снимок. Не следует представлять ручной догон как восстановление истории.
- В этой среде установка, сетевые скачивания и запуск сервисов запрещены; интеграционная проверка и фактические результаты оставлены на утро. Коммиты запрещены локальными правилами проекта.
